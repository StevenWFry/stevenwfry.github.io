tmux for Beginners.
// one terminal, infinite terminals.

tmux turns one terminal window into sessions, windows, and panes that survive disconnects, reboots of your SSH connection, and your own accidental Cmd-W. This is the smallest set of commands and habits that makes it stick.

$ tmux new -s dev
[detached terminal multiplexer activated]
$ ssh box "long running job" && close laptop
job still running. tmux does not care about your Wi-Fi.
$ tmux attach -t dev

The 30-second model

tmux has exactly three layers. Once this hierarchy clicks, every command makes sense.

  • Session — a workspace that lives on the server side, independent of your terminal window. Close the terminal; the session keeps running.
  • Window — a full-screen tab inside a session. Like browser tabs, but for shells.
  • Pane — a split inside a window. Editor on the left, logs on the right, that kind of thing.
// why bother
Two killer features: your work survives SSH disconnects, and you stop juggling terminal windows. Everything lives in one place, addressable by name. If you already use Neovim splits, tmux is the same idea one level up — see Neovim for Beginners.

First session

start named, always 
tmux new -s dev     # new session called "dev"
tmux ls             # list sessions (from outside tmux)
tmux attach -t dev  # reattach to it later
// name your sessions
Plain tmux works but gives you sessions named 0, 1, 2... and in a week you will have no idea which is which. tmux new -s projectname costs four extra keystrokes and saves your sanity.

The prefix key

Inside tmux, every command starts with the prefix: Ctrl-b by default. Press prefix, release, then press the command key. Ctrl-b then % splits the screen. You are not holding all three keys at once.

the pattern 
# prefix, then key:
Ctrl-b  %      # split vertically
Ctrl-b  c      # new window
Ctrl-b  d      # detach
Ctrl-b  ?      # list ALL keybindings (q to exit)
// most popular remap
Many people rebind the prefix to Ctrl-a because it is easier to reach. The config section below shows how. This guide writes prefix from here on — use whichever you set.

Panes

Panes are where tmux starts feeling like a tiling window manager that lives in your terminal.

Create and close

prefix %     split left/right
prefix "     split top/bottom
prefix x     kill current pane
exit         or just exit the shell

Navigate and resize

prefix ←↑↓→  move between panes
prefix o     cycle panes
prefix z     zoom pane fullscreen (toggle)
prefix Ctrl-←↑↓→ resize pane
// the zoom trick
prefix z is the single most useful pane command. Temporarily fullscreen the pane you care about, press it again to restore the layout. No more squinting at logs in a quarter of the screen.

Windows

window basics 
prefix c      # create window
prefix ,      # rename window
prefix n      # next window
prefix p      # previous window
prefix 0-9    # jump to window by number
prefix w      # interactive window picker
prefix &      # kill window (asks first)

A common layout: window 1 named edit (Neovim), window 2 named run (server/tests), window 3 named git. Rename them — the status bar becomes a map of your project instead of a row of zsh labels.

Sessions, detach, attach

This is the feature that makes tmux non-negotiable for SSH work.

the detach/attach loop 
prefix d               # detach — session keeps running
tmux ls                # see what is running
tmux attach -t dev     # pick up exactly where you left off
tmux kill-session -t dev  # actually end it
the ssh workflow 
# on the remote box:
ssh you@server
tmux new -s work       # or: tmux attach -t work
# ... start a long job ...
# Wi-Fi dies / laptop sleeps / you go home. job keeps running.
ssh you@server
tmux attach -t work    # everything still there
// attach-or-create one-liner
tmux new -A -s work attaches to work if it exists, creates it if not. Perfect for shell aliases and SSH habits.

Scrolling and copy mode

The first thing every beginner hits: the mouse wheel does nothing and you can't scroll up. tmux has its own scrollback called copy mode.

copy mode basics 
prefix [      # enter copy mode (now you can scroll)
↑↓ / PgUp     # move around
q             # quit copy mode

# with vi keys enabled in the config below:
v             # start selection
y             # yank selection and exit
prefix ]      # paste inside tmux
// or just enable the mouse
The config below turns on mouse support: scroll wheel scrolls, clicking switches panes, dragging borders resizes. Purists scoff. Ignore them — it's one line and it makes week one painless.

Minimal config

tmux reads ~/.tmux.conf at startup. This is a sane starter — small enough to understand every line.

create config 
nvim ~/.tmux.conf
~/.tmux.conf 
# prefix: Ctrl-a instead of Ctrl-b
unbind C-b
set -g prefix C-a
bind C-a send-prefix

# quality of life
set -g mouse on              # scroll, click panes, drag borders
set -g base-index 1          # windows start at 1, matches keyboard row
setw -g pane-base-index 1
set -g renumber-windows on   # no gaps after closing windows
set -g history-limit 50000   # bigger scrollback
set -g escape-time 10        # no Esc delay (Neovim users want this)

# vi keys in copy mode
setw -g mode-keys vi
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-selection-and-cancel

# saner splits: | and - instead of % and "
bind | split-window -h
bind - split-window -v

# true color (matches modern terminals)
set -g default-terminal "tmux-256color"
set -ag terminal-overrides ",xterm-256color:RGB"
apply it 
# from a shell inside tmux:
tmux source-file ~/.tmux.conf

# or kill the server and start clean:
tmux kill-server
tmux new -s dev
// skip plugins for now
Yes, TPM and the plugin ecosystem exist. Like with Neovim: build the muscle memory first, decorate later. Everything in this guide is stock tmux.

Practice plan (7 days)

  • Day 1: Start a named session, detach with prefix d, reattach. Repeat until boring.
  • Day 2: Live in two panes: editor + shell. Use prefix z to zoom.
  • Day 3: Add windows. Rename them with prefix ,. Jump by number.
  • Day 4: Install the config above. Re-learn your splits as | and -.
  • Day 5: Enter copy mode, scroll a long log, yank a line, paste it.
  • Day 6: SSH somewhere, run something slow in tmux, disconnect on purpose, reattach.
  • Day 7: One full work session entirely inside one tmux session. No extra terminal windows allowed.

Cheat sheet

daily core 
tmux new -s name       # new named session
tmux new -A -s name    # attach or create
tmux ls                # list sessions
tmux attach -t name    # reattach
prefix d               # detach
prefix c , n p 0-9     # windows: new, rename, next, prev, jump
prefix % "             # split (or | and - with config)
prefix ←↑↓→            # move between panes
prefix z               # zoom pane
prefix x               # kill pane
prefix [               # copy mode / scrollback
prefix ?               # all keybindings

Common issues

I can't scroll up
That's copy mode: prefix [, then arrows or PgUp, q to leave. Or add set -g mouse on to ~/.tmux.conf and the wheel just works.
Colors look wrong in Neovim inside tmux
Add the two default-terminal / terminal-overrides lines from the config section, restart the tmux server (tmux kill-server), and reattach.
Esc is laggy in Neovim
tmux waits to see if Esc starts an escape sequence. set -g escape-time 10 fixes it.
Changed the config but nothing happened
~/.tmux.conf is only read when the server starts. Run tmux source-file ~/.tmux.conf inside tmux, or tmux kill-server and start fresh. Detaching is not enough — the server keeps running.
"lost server" or "no sessions" after reboot
tmux sessions live in memory — a real reboot ends them. That's expected. (Persisting across reboots is plugin territory: tmux-resurrect, when you're ready.)
